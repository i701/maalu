# Docker images, deployment, backups and restore drill

Docker images: `apps/api/Dockerfile` and `apps/web/Dockerfile`, both built from the repository root (`docker build -f apps/web/Dockerfile .`), since they need the root lockfiles. `.github/workflows/docker.yml` publishes `ghcr.io/i701/maalu-api` and `maalu-web` for amd64 and arm64: `:latest` and `:sha-<commit>` from main, `:X.Y.Z` and `:X.Y` from a `vX.Y.Z` tag, and pull requests only build. `docker-compose.prod.yml` runs them with Postgres (secrets in a `.env` beside it). The API image runs `alembic upgrade head` before serving. The web image serves the production build with srvx (`pnpm --filter @maalu/web start`), whose `--static` path is relative to the entry file, hence `../client`; the build and production dependencies are plain JS made on the builder's platform. In production the session cookie is `Secure`, so the app needs HTTPS (or localhost). **`scripts/restore-drill.sh`** rehearses a restore of the real data on a server that has only the compose file and `.env` (it is fetched with `curl` from the raw GitHub URL): it takes a `pg_dump -Fc` of the running database, starts a throwaway second project (`maalu-drill`, its own volumes, `127.0.0.1:3999`), `pg_restore`s into it, compares every table's row count (within what changed while it ran; the `procrastinate_*` queue tables are skipped) and the Alembic version, starts only the copy's API and web (**never the worker, and the receipts-bucket settings are blanked, so the copy cannot touch the real bucket**), checks the sign-in page, the API and the user count, copies receipts through `tar` when they are in the volume, prints PASS or FAIL and removes the copy (`--keep` leaves it, `--save-dump DIR` keeps the dump). **The copy is only torn down when this run created it** (`OWN_COPY`): an earlier version also tore down a project it had just refused to use, which would have deleted the live install had `DRILL_PROJECT` matched its name, so keep that guard. **`scripts/backup.sh`** is the nightly offsite backup, kept deliberately small (a full server-backup job inside the API, with a Settings card, a `restore` admin command and notifications, was built and tested on 2026-11-09 and then **dropped as overkill**: do not rebuild it, a script on the server is enough). Run from cron in the folder with the compose file and `.env`: `pg_dump -Fc` inside the `db` container (so the password never leaves it and the client is the server's own version), `age -r $AGE_RECIPIENT` (a public key; the private key stays off the server), then `rclone copy` to `$RCLONE_DEST` (a separate bucket from the receipts), checked with `rclone lsf` before the local file is removed, then `rclone delete --min-age ${RETENTION_DAYS:-30}d --include 'maalu-*.dump.age'` (only files named like ours). The file is `maalu-<UTC date>T<HHMMSS>Z-<12-char commit>.dump.age`, the commit read from the running api container's `org.opencontainers.image.revision` label (the published images have it, so no build change is needed). It reads only the settings it needs from the compose `.env` (a value like `MAP_ATTRIBUTION=&copy;` would break `source`; the environment wins), refuses a bad or missing `AGE_RECIPIENT`, removes a dump that is not complete but **keeps a good dump whose upload failed**, rejects a dump under 5,000 bytes, never overwrites a file, and sends a **Telegram message only on failure** (the token goes in through curl's stdin config, never `ps`). No `RCLONE_DEST` = test mode: the encrypted dump stays in the folder. Restore is the manual five steps in the Obsidian guide (`age -d` first); `restore-drill.sh` proves it without touching the live install. Tested 2026-11-09 against an install built from the published images with real `rclone` (a local folder as the destination) and `age`: upload, retention (old `maalu-*` files go, other files and recent ones stay), the failure paths with a fake `curl`, a backup restored into a fresh Postgres with matching rows; **not** tested against a real R2 bucket. `.env.prod.example` (at the repo root, un-ignored in `.gitignore`: `.env.*` used to hide it) lists every deployment setting.
